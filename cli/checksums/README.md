# Release checksums

One file per CLI release, `<version>.txt`, in `sha256sum` format. clawd.gg
serves them at `https://clawd.gg/install/checksums/<version>.txt` and
`scripts/install.sh` verifies every download against them.

**This directory is a security boundary.** The binary comes from GitHub
Releases; the hash comes from here. Neither host alone can make anyone run a
swapped binary — an attacker holding the GitHub release still needs clawd.gg to
serve a matching hash, and an attacker holding clawd.gg still needs a matching
binary on GitHub. `install.sh` refuses to install when the hash is missing or
does not match, so a version with no file here is simply not installable.

Generated by `bun scripts/build-cli.ts --all --checksums`, which writes this
copy and the one that rides along with the release. They are the same bytes.

## Release procedure

The order matters: the checksums must be live before the install link is.

1. **Bump** `cli/package.json` to the new version and commit it.
2. **Tag and push**: `git tag cli-v<version> && git push origin cli-v<version>`.
   The tag's version must match `cli/package.json` or `release-cli.yml` refuses
   to build.
3. **Wait for the release workflow.** It cross-compiles all eight targets,
   verifies each one's checksum, runs the native binary, attests build
   provenance, and uploads the assets to the `cli-v<version>` release. It does
   not overwrite an existing asset, so a re-run on a published tag fails rather
   than silently replacing a binary people have already downloaded.
4. **Commit the checksums.** Download `checksums.txt` from the release (or run
   `bun scripts/build-cli.ts --all --checksums` locally and confirm the hashes
   are identical), save it as `cli/checksums/<version>.txt`, and commit.
5. **Deploy**: `scripts/deploy.sh` then the `up -d` step from the runbook. Until
   this lands, `https://clawd.gg/install` installs the PREVIOUS version and
   anyone pinning `CLAWDGG_VERSION=<new>` gets a clear refusal — never an
   unverified binary.
6. **Verify from outside**:

   ```sh
   curl -fsSL https://clawd.gg/install/checksums/<version>.txt
   CLAWDGG_VERSION=<version> sh -c "$(curl -fsSL https://clawd.gg/install)"
   clawdgg version
   ```

7. **Publish to npm** (optional, for `bunx clawdgg`): from `cli/`, `npm publish`.

## Verifying a download by hand

```sh
curl -fsSLO https://clawd.gg/install/checksums/2.0.0.txt
shasum -a 256 -c 2.0.0.txt --ignore-missing
```
